Abstract—The integration of Large Language Models (LLMs) into automated software engineering workflows has transitioned from single-prompt code completion toward multi-agent collaborative synthesis. However, existing multi-agent systems suffer from three fundamental limitations: (i) extreme API token expenditure and quota exhaustion caused by unconstrained inter-agent conversational chatter ($O(N^2)$ communication overhead), (ii) destructive regeneration during follow-up modification cycles wherein entire working codebases are discarded and rewritten from scratch, and (iii) rigid homogeneous provider reliance that lacks cost-aware heterogeneous model routing and edge-hosted Small Language Model (SLM) integration. This paper presents an autonomous, state-graph-orchestrated multi-agent software engineering framework developed using LangGraph, FastAPI, Node.js/Express, and React. The system introduces a cost-bounded dual-call generation paradigm that decouples cognitive planning from specialist code synthesis, completing full multi-tier full-stack application synthesis in strictly two upstream LLM invocations while offloading architectural specifications, test suites, QA linting, and documentation to deterministic AST agents. To prevent destructive regeneration, we introduce a 7-stage context-preserving refinement pipeline that computes file-dependency trees and executes surgical in-place modifications on disk. A resilient cascading fallback chain (Gemini → Groq → OpenRouter → Ollama → OpenAI → AST Mock) with per-file sub-token decomposition ensures continuous operational availability under severe rate-limiting. Empirical evaluations across 50 diverse full-stack development tasks demonstrate a 68.4% reduction in API token consumption and a 94.2% first-pass compilation rate relative to unconstrained communicative baselines.
Index Terms—Multi-Agent Systems, Large Language Models, Software Engineering Automation, LangGraph, Heterogeneous Model Routing, Incremental Code Refinement, StateGraph, Quota Resilience, Full-Stack Synthesis.

I. INTRODUCTION

Software engineering encompasses complex cognitive workflows including requirement elicitation, architectural partitioning, full-stack implementation, automated testing, quality assurance (QA), and documentation. While generative Large Language Models (LLMs) such as GPT-4, Gemini 2.5, and Claude 3.5 have exhibited remarkable natural language reasoning and source code generation abilities, single-shot monolithic generation models exhibit fundamental limitations when generating complete multi-file systems.

First, context window saturation and attention dispersion in monolithic prompts frequently induce missing imports, syntax truncation, and orphaned API contracts between backend routes and frontend components. Second, existing multi-agent frameworks (e.g., ChatDev, MetaGPT) employ unconstrained multi-turn natural language dialogues between simulated personas. In practice, this open-ended conversational chatter consumes upwards of 40,000 tokens per run, rapidly triggering rate limits (HTTP 429) on commercial API tiers. Third, existing tools suffer from destructive regeneration: when a user requests an incremental modification (e.g., "add a dark mode toggle" or "add a password reset route"), the entire repository is regenerated from scratch, destroying existing working code, state logic, and manual edits.

To overcome these challenges, this paper presents an autonomous multi-agent software engineering framework built on LangGraph, FastAPI, Express.js, and React. The system guarantees a cost-bounded 2-call LLM generation budget, a non-destructive 7-stage AST-aware incremental refinement engine, and an intelligent cascading fallback routing architecture that bridges cloud models with local small language models (SLMs). The primary contributions of this work are:

  • Cost-Bounded Dual-Call StateGraph Architecture: A hybrid deterministic-agent workflow that delivers complete multi-tier software projects using strictly two cloud LLM invocations (Planner and Coder), eliminating conversational token leakage.
  • Context-Preserving 7-Stage Incremental Refinement: A non-destructive refinement DAG that parses existing on-disk source files, identifies semantic change intent, and applies surgical in-place modifications without repository destruction.
  • Heterogeneous Model Routing & Resilient Quota Cascading: An adaptive routing protocol that decouples reasoning from heavy token synthesis, cascading across Gemini, Groq, OpenRouter, local Ollama (Qwen2.5-Coder), and OpenAI with differentiated HTTP 429 retry logic.
  • Per-File Sub-Token Context Decomposition: An automated decomposition routine for edge SLMs that prevents token delimiter corruption and file truncation on resource-constrained local hardware.

II. RELATED WORK

A. Monolithic LLM Code Generation: Early benchmarks on models such as Codex and GPT-4 demonstrated that single-prompt code generation performs well on isolated algorithmic functions but degrades precipitously when generating complex multi-file software repositories due to context window limits and lack of closed-loop verification [2], [4].

B. Communicative Multi-Agent Systems: Frameworks like ChatDev [6] and MetaGPT [7] introduced role-playing agents simulating software teams. However, their reliance on unconstrained conversational dialogues induces high latency, stochastic conversational drift, and extreme token costs. Our framework replaces conversational chatter with a mathematically defined LangGraph StateGraph where inter-agent transitions occur via structured schemas.

C. LLM Quota Optimization & Incremental Refinement: Previous studies on LLM inference resilience [1], [3], [5] emphasize that real-world deployment requires cost-predictable pipelines and failover guarantees. The proposed system extends these concepts by combining deterministic AST validation agents with an in-place diff modification engine.

III. SYSTEM ARCHITECTURE AND METHODOLOGY

A. Mathematical State Model & Execution DAG

The system execution state $\mathcal{S}_t \in \Sigma$ over the LangGraph StateGraph is formally represented by:

$\mathcal{S}_t = \Big( \mathcal{U}, \mathcal{T}_{ ext{proj}}, \Phi_{ ext{plan}}, \Psi_{ ext{arch}}, \mathcal{F}, \mathcal{R}_{ ext{qa}}, k_{ ext{retry}}, \mathcal{E} \Big)$

where $\mathcal{U}$ is the natural language requirement prompt, $\mathcal{T}_{ ext{proj}}$ is the detected project taxonomy, $\Phi_{ ext{plan}}$ is the structured plan, $\Psi_{ ext{arch}} = \{f_1, f_2, \dots, f_n\}$ is the file manifest, $\mathcal{F} = \{f_i \mapsto c_i\}$ maps relative paths to source code contents, $\mathcal{R}_{ ext{qa}}$ contains validation logs, $k_{ ext{retry}} \in \mathbb{N}$ is the loop counter ($k_{ ext{retry}} \le 2$), and $\mathcal{E}$ stores fatal error flags.

Fig. 1. Topological state transition graph of the Dual-Call Software Generation Pipeline.

B. Specialist Agent Functional Decomposition

1) Planner Agent: Decomposes prompt $\mathcal{U}$ into project taxonomy $\mathcal{T}_{ ext{proj}}$, milestones, and API boundaries (LLM Call 1).

2) Architecture Agent: Deterministically resolves build configurations (`package.json`, `vite.config.js`) and generates file manifest $\Psi_{ ext{arch}}$.

3) Coder / Specialist Agents: Synthesizes concrete source logic in batch or per-file mode (LLM Call 2).

4) Tester Agent: Parses module exports to deterministically generate Jest / PyTest test files.

5) QA Review Agent: Executes AST parsing, syntax validation, and tag parity checks with feedback routing.

6) Doc Writer Agent: Generates comprehensive `README.md` documentation and archives artifacts.

IV. SYSTEM WORKFLOW & REFINEMENT ALGORITHMS

ALGORITHM 1: Dual-Call Bounded Generation Pipeline
1: Input: User Requirement Prompt $\mathcal{U}$, Config $\mathcal{P}$
2: Output: Complete Codebase $\mathcal{F}$, Audit State $\mathcal{S}$
3: $\mathcal{S} \leftarrow \{ ext{prompt}: \mathcal{U}, ext{retry\_count}: 0, ext{files}: \{\} \}$
4: $( ext{Plan}, \mathcal{T}_{ ext{proj}}) \leftarrow ext{LLM\_Invoke}( ext{PlannerPrompt}(\mathcal{U}), \mathcal{P}. ext{Planner})$
5: $\Psi_{ ext{arch}} \leftarrow ext{GenerateManifest}(\mathcal{T}_{ ext{proj}}, ext{Plan})$
6: if $\mathcal{P}. ext{Coder}. ext{is\_local}$ then
7:   for each $f_i \in \Psi_{ ext{arch}}$ do $\mathcal{F}[f_i] \leftarrow ext{LLM\_Invoke\_PerFile}(f_i, ext{Plan})$ end for
8: else
9:   $\mathcal{F} \leftarrow ext{ParseDelimiters}( ext{LLM\_Invoke\_Batch}( ext{CoderPrompt}( ext{Plan}, \Psi_{ ext{arch}})))$
10: end if
11: $\mathcal{S}. ext{test\_files} \leftarrow ext{SynthesizeTests}(\mathcal{F})$
12: while $ ext{QAScore}(\mathcal{F}) < 80 ext{ and } \mathcal{S}.k_{ ext{retry}} \le 2$ do
13:   $\mathcal{S}.k_{ ext{retry}} \leftarrow \mathcal{S}.k_{ ext{retry}} + 1$; $\mathcal{F} \leftarrow ext{PatchAST}(\mathcal{F})$
14: end while
15: $\mathcal{F}[ ext{"README.md"}] \leftarrow ext{GenerateDocs}( ext{Plan}, \mathcal{F})$
16: $ ext{PersistDiskAndDB}(\mathcal{F}, ext{SessionID})$; return $\mathcal{S}$
ALGORITHM 2: Context-Preserving Incremental Refinement
1: Input: Change Prompt $\Delta\mathcal{U}$, SessionID, Root Directory
2: Output: Updated Codebase with Surgical In-Place Diffs
3: $\mathcal{F}_{ ext{disk}} \leftarrow ext{ReadWorkspaceFromDisk}( ext{SessionID})$
4: $\mathcal{T}_{ ext{ast}} \leftarrow ext{ParseDirectoryStructure}(\mathcal{F}_{ ext{disk}})$
5: $ ext{Intent} \leftarrow ext{LLM\_AnalyzeIntent}(\Delta\mathcal{U}, \mathcal{T}_{ ext{ast}})$
6: $\mathcal{F}_{ ext{target}} \leftarrow ext{IdentifyAffectedFiles}( ext{Intent}, \mathcal{T}_{ ext{ast}})$
7: for each $f_j \in \mathcal{F}_{ ext{target}}$ do
8:   $\mathcal{F}_{ ext{disk}}[f_j] \leftarrow ext{LLM\_RewriteFile}(\mathcal{F}_{ ext{disk}}[f_j], \Delta\mathcal{U}, ext{Intent})$
9:   $ ext{WriteToDisk}( ext{SessionID}, f_j, \mathcal{F}_{ ext{disk}}[f_j])$
10: end for
11: $ ext{DiffReport} \leftarrow ext{DiffQAVerification}(\mathcal{F}_{ ext{target}}, \mathcal{F}_{ ext{disk}})$
12: $ ext{UpdateMongoHistory}( ext{SessionID}, \Delta\mathcal{U}, ext{DiffReport})$; return $\mathcal{F}_{ ext{disk}}$

IX. CONCLUSION AND FUTURE WORK

This paper presented an autonomous multi-agent software engineering orchestration system engineered with LangGraph, Node.js, FastAPI, and React. By combining a mathematically bounded 2-Call StateGraph architecture with a context-preserving 7-stage incremental refinement pipeline and a resilient multi-provider fallback cascade, the system enables cost-effective, non-destructive software engineering automation. Future work includes integrating isolated WebAssembly runtime sandboxes for live dynamic testing and supporting multi-modal Figma design ingest.
